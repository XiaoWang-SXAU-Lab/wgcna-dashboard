# Project + Copilot 探索开发计划

日期：2026-10-31（Asia/Hong_Kong）
分支：`explore/project-copilot`；起点：`c9409e3`（dashboard v0.6.0）。

## 目标与边界

用户能够新建项目、关闭软件、重新打开后恢复参数、有效结果和操作位置；研究问题卡与分析证据共同持久化，随后接入半自主 Copilot。

优先复用 Go/Vue/Rust worker 的按步骤管线。第一版不做桌面 pet、不做步骤内部断点续算、不做多人实时协作、不引入通用任意代码执行。2026-10-31 已完成核心、HTTP 与首版 `/projects` 工作区，Windows 已验证过滤/SFT/网络保存恢复；当前契约与限制见 `PROJECT_CONTRACT.md`。

## 现状（源码检查所得）

- `backend/internal/job/job.go` 已保存输入、params 和 worker 输出，但 Manager 重启创建空 jobs map；DoneSteps 等状态未完整落盘。
- `frontend/src/stores/wgcna.ts` 保存内存状态，缺乏项目打开和完整 hydration。
- server 未指定 `WGCNA_JOBS_DIR` 时使用系统临时目录。
- 已有按步骤运行及下游失效逻辑；报告快照和 report-latest 只解决报告，不等于恢复分析。
- 已有双平台隔离构建脚本；Mac 实机验证情况须在交接中重新确认。

## 数据模型建议（M1 开始前确定接口）

Project 包含稳定 UUID、schema_version、项目名、时间、研究问题卡、输入索引和分析列表。Analysis 包含编辑参数、执行参数快照、步骤记录、结果索引和界面状态。Job 是一次执行，不再等同整个项目。

建议目录：

```text
project.json
inputs/
analyses/baseline/params.json
analyses/baseline/state.json
analyses/baseline/results/
analyses/baseline/logs/
copilot/
reports/
```

初版 JSON + 文件即可。ProjectState 是内存中的统一视图，大矩阵和网络独立保存，按需加载；不要序列化浏览器 File、图表实例或进程对象。

默认复制输入进项目；项目内引用使用相对路径。外部文件引用延后。最近项目列表、绝对路径、API 密钥、窗口及本机工具配置存放本机应用数据目录。已有项目路径使用用户选择的持久目录，不放临时缓存。

每个步骤至少记录：执行 ID、状态、输入摘要、实际执行参数、上游输出指纹、引擎版本/构建指纹、必要结果清单与校验、起止时间、错误。完整性和依赖有效性共同决定缓存是否可用。改参后旧结果可查看但必须标注对应旧参数和过期状态。

## M0：本机环境与契约

1. 检查两仓库状态、现有 worker 输入输出、API 和界面流程。
2. 验证 Node/pnpm store、Go cache/module cache、Cargo home/target、R library/runtime 及临时目录都在本机非同步路径。
3. 形成 Project/Analysis/Step schema、API 和恢复状态转换约定；保留 schema 版本与迁移入口。
4. 修订隔离开发/验证方式：现脚本只复制部分源目录，新增 schema/fixture 若被使用须纳入复制范围；本地测试不可回退到同步盘安装依赖。

验收：环境路径检查可复现；确认本机构建不污染同步源码；接口文档清晰。机器无法运行的检查留待对应平台，不假报完成。

## M1：项目持久化与打开

- 实现 create/open/read/update 项目；打开时校验路径、schema、必需文件并重建运行状态。
- 小型状态文件采用临时文件写入再替换，按平台验证行为；序列化写入、处理失败并保留有效备份。多文件结果用成功清单提交，未提交结果不可命中缓存。
- 重启后 running 转为 interrupted；先确认是否有存活 worker/写入者，禁止直接重复启动。实现项目写入锁及过期锁识别，不以跨机器 PID 单独判定存活。
- 复用有效上游；中断步骤从该步骤重跑。持久项目不能由启动脚本当缓存清理。
- 旧临时 job 仅提供显式导入/恢复入口：缺少执行来源证据时标记未验证，不凭历史文件自动认定有效。

验收：完成 filter/SFT 后真正退出并重启后端，打开项目可读取有效输出；中断网络计算后上游保留；损坏 JSON、缺结果、改输入、改参数均有准确状态及错误提示；写入失败不显示保存成功。

## M2：项目入口与自动保存

2026-10-31 用户确认的 UI 调整：首版 ProjectView 集中所有步骤且隐藏旧 navbar 仅为临时措施。下一迭代 Project 回归管理入口，原导航/各分析页面保留并接入统一当前 Project；顶部展示项目名称和保存状态。无项目时禁用分析入口或引导打开。优先此整合，再扩展助手与其他功能。

- 首页：新建/打开/最近项目；Data Import 成为项目内部的数据步骤。
- 恢复编辑参数、结果执行参数、排除样本、trait source、当前模块/性状、当前页；不强行恢复临时交互对象。
- 编辑后短延迟自动保存，运行边界立即保存；离开/关闭前处理待写入状态，显示保存中/已保存/失败。
- hydration 期间抑制 watcher 的意外默认值重置和运行；加载完成再统一校验选择。

验收：β=6 结果完成，编辑为 8 未运行，关闭后重开仍显示编辑值 8、结果来自 6、下游待更新；重载界面、重启进程、复制项目到另一目录分别验证。

## M3：研究问题卡

字段：核心问题、假设、物种/组织、实验因素、重复与配对、批次、可用表型、目标输出、限制、未决问题。允许空缺和渐进补充，不阻塞数据探索。

区分用户陈述、程序检验和助手建议，记录来源和变更历史。更改问题卡不应无理由触发网络重算；更改影响计算的设计/变量映射则走依赖失效规则。

验收：可保存、重开、编辑；可追踪结论依据，敏感机器配置不混入卡片。

## M4：最小 Copilot 闭环

先做一个场景：模块与表型不显著时的诊断。建立受控工具：读取项目摘要/设计、读取检查结果、提出分析计划、执行已授权诊断、比较结果、保存决策和证据。

skill 写清输入、工具、分支、停止条件及结构化输出。对话与正式项目状态分离；每条分析结论关联 execution/result ID。数据更新后标注旧结论失效。不得以显著性作为搜索优化目标，不静默删样本或覆盖基线。可重复的只读诊断与探索分支按授权执行。

验收：系统能指出信息缺口、调用真实工具、给出可复核依据，并能结束于“证据不足”；退出重开后知道已做什么和下一步，而非只恢复聊天文本。

## M5：双平台与论文评估准备

Windows/Mac 分别实机验证新建、自动保存、进程退出、重新打开、移动项目、带空格/中文路径、不同引擎版本和缺少 R 的提示。共享项目内容应跨平台；二进制和依赖不随项目迁移。

针对持久化与缓存写必要的 Go 集成测试及前端状态恢复验证。保留已有科学一致性与报告回归；仅当修改 worker 数学行为时扩展科学对拍。后续建立普通工作流、普通问答、完整 Copilot 对照，评估决策正确性、复现性、误导结论率及用户时间，不以回答流畅度替代准确性。

## 推荐交付节奏

按 M0 → M1 → M2 → M3 → M4 → M5 推进。每阶段小步提交并留验收记录，提交按用户授权操作。先打通保存/重开闭环，再扩展助手；暂不承诺日历工期。
